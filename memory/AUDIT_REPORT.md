## 1. Architecture Overview

| Слой | Технологии | Размер |
|---|---|---|
| Frontend | React 19, CRA 5 + craco, Tailwind, shadcn/ui, axios, react-router 7, framer-motion | ~41 тыс. строк, 38 страниц, 127 компонентов, 6 контекстов |
| Backend | Python 3.11, FastAPI 0.110, Starlette 0.37, motor/pymongo, PyJWT, bcrypt | ~17,6 тыс. строк, 37 роутеров, 404 эндпоинта |
| База | MongoDB, 56 коллекций и 2 новые служебные (`login_attempts`, `merged_orders_archive`), строковые UUID в поле `id` | индексы добавлены (раздел 4) |
| Тесты | 44 файла pytest, работают по HTTP с preview-API и preview-базой | фронтенд-тестов и CI нет |

Авторизация: JWT HS256 на 7 дней, выдаётся в теле ответа и в HttpOnly-cookie; backend принимает заголовок `Authorization: Bearer` или cookie. Роли: `user`, `manager`, `admin`; проверка роли — в каждом обработчике, реальная защита на стороне API.

Способы оплаты после изменений: наличные, баланс, отсрочка, криптовалюта, перевод на карту по реквизитам, которые администратор выдаёт вручную по каждому заказу.

Внешние интеграции: Cloudinary (файлы), Resend (почта), Telegram Bot API (чат поддержки), блокчейн-проверка крипто-платежей, LLM через Emergent-ключ.

## 2. Что исправлено

### Деньги и оплата

| Проблема | Что сделано | Проверка |
|---|---|---|
| Баланс пополнялся мгновенно без платежа (карта и криптовалюта) | Пополнение стало заявкой. Баланс меняется только после кнопки администратора «Деньги получены — зачислить». Для карты администратор выдаёт реквизиты, клиент видит их в истории баланса. Заявку можно отклонить. | автотест + проверка в интерфейсе |
| Двойное нажатие «зачислить» | Зачисление срабатывает один раз | автотест (4 одновременных запроса — одно зачисление) |
| Сторонний платёжный шлюз для карт | Удалён полностью: эндпоинты, модели, библиотека, подписи в админке | поиск по проекту — упоминаний нет |
| Режим «общие реквизиты видны клиенту сразу» | Убран. Реквизиты по заказу выдаёт только администратор; в настройках остался шаблон реквизитов, клиентам он не отдаётся | автотест + интерфейс |
| Один крипто-перевод можно было зачесть нескольким заказам | Повторно использованная транзакция отклоняется; в базе — уникальный индекс | код + индекс; автотеста с реальным переводом нет |
| Клиент мог привязать крипто-транзакцию к чужому заказу | Проверяется владелец заказа и что оплата ещё ожидается | автотест |
| Списание с баланса и призовых баллов без защиты от гонки | Списание условное: проходит, только если средств хватает в момент списания | код; автотеста на гонку нет |

### Заказы и склад

| Проблема | Что сделано | Проверка |
|---|---|---|
| Заказ создавался и оплачивался, а товар со склада не списывался | Товар резервируется до любых списаний. Если товара не хватило — заказ не создаётся; при любой ошибке оформления резерв возвращается | автотест: два одновременных заказа на последнюю единицу — один получает отказ |
| Публичный адрес отмены просроченных заказов каждый раз заново возвращал товар на склад | Только для администратора; заказ отменяется и возвращается на склад один раз | автотест на доступ |
| Две одновременные отмены заказа дважды возвращали товар и деньги | Отмена срабатывает один раз | автотест (3 одновременных запроса — одна отмена, остаток восстановлен один раз) |
| Объединение заказов теряло оплату, скидки и привязку к складам | Итог — сумма итогов исходных заказов; переносятся оплата с баланса, кэшбэк, доставка, статус оплаты, складские привязки; ссылки на заказ в отсрочках, операциях и движениях переводятся на новый заказ; исходные заказы сохраняются в архивной коллекции `merged_orders_archive` | автотест (итог, складские привязки, возврат остатка при отмене); перенос оплаты с баланса и ссылок отдельным тестом не покрыт |

### Доступ и защита

| Проблема | Что сделано | Проверка |
|---|---|---|
| Пароли сохранялись в открытом виде | Новые и изменённые пароли больше не сохраняются в открытом виде; при смене пароля старая открытая копия стирается; открытый пароль не отдаётся менеджерам и в общий профиль | автотест |

| Нет ограничения попыток входа | 10 неверных попыток за 15 минут с одного адреса (50 на один e-mail со всех адресов) — вход блокируется, сайт показывает сообщение | автотест + интерфейс |
| Нет ограничения на письма восстановления пароля | 5 запросов за 15 минут на один e-mail | код |

| Загрузка любых типов файлов | Запрещены исполняемые в браузере и системе типы (html, svg, js, exe и др.) | автотест |
| Заголовок `X-Content-Type-Options` | Добавлен ко всем ответам API | код |

## 3. Что остаётся открытым

### Нужны ваши решения (поведение сайта не менялось)

1. **Пароли в админке.** Уже сохранённые открытые пароли старых клиентов остались в базе и видны администратору. Удалить их и убрать показ — или оставить?
2. **Отмена заказа, оплаченного картой или криптовалютой.** Деньги автоматически не возвращаются (возвращается только оплата с баланса). Сделать автоматический возврат на баланс — или возврат остаётся ручным?
3. **Частичная отгрузка.** Неотгруженный остаток на склад не возвращается. Возвращать автоматически?
4. **Регистр e-mail.** Вход чувствителен к регистру букв, восстановление пароля — нет. Привести к одному виду?

## 4. Performance Audit

Сделано: индексы; отложенная загрузка кабинетов персонала.

- каждый авторизованный запрос делает 2 чтения базы, каждый изменяющий — ещё одно в журнале действий;

- фоновая задача отмены заказов работает внутри веб-процесса: при нескольких процессах запустится в каждом.

## 9. Подготовка backend/API к Android

1. Вход по заголовку `Bearer` уже работает. Нужны: короткий access-токен и refresh-токен, отзыв токенов, список устройств.
2. Версия API `/api/v1`, старые пути оставить.
3. Единый формат ошибок: код и текст; 401 вместо 403 без токена.
4. Постраничная выдача всех списков.
5. Модели ответов для всех эндпоинтов — для генерации клиента из `/openapi.json`.
6. Цены и итоги считает только сервер.
7. Push-уведомления вместо опроса каждые 3–30 секунд.
8. Ключ идемпотентности для создания заказа и заявки на пополнение.
9. Ограничение частоты запросов по пользователю и устройству.
10. Параметры POST-запросов — в теле, не в адресе.
11. Эндпоинт минимально поддерживаемой версии приложения.
12. Деньги — в копейках или строкой; даты — ISO 8601 в UTC.
